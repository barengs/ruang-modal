Analisa Performa Terhadap Ekosistem Ruang Modal berbasis Web

Performance Analysis of Web-Based Ruang Modal Ecosystem

Abstrak
Transformasi digital pemberdayaan alumni SMA Double Track melalui platform Ekosistem Ruang Modal—yang mengintegrasikan layanan Ruang Modal, Ruang Tumbuh, Ruang Pasar, dan Monitoring—menuntut arsitektur web yang andal, aman, dan responsif. Migrasi sistem dari layanan berbasis skrip spreadsheet ke arsitektur Hybrid Monolith menggunakan Laravel 13, React.js 18, Vite 8, Redux Toolkit, TanStack Table, TanStack Chart, autentikasi JSON Web Token (JWT), serta otorisasi Role-Based Access Control (RBAC) Spatie Permission menghadirkan kompleksitas baru pada sisi frontend maupun backend. Penelitian ini bertujuan menganalisis performa Ekosistem Ruang Modal berbasis web secara menyeluruh (end-to-end) mencakup efisiensi bundle frontend, profil eksekusi query SQL dan memori server, serta ketahanan beban konkuren HTTP. Metode yang digunakan adalah deskriptif kuantitatif eksperimental melalui tiga lapis pengujian: (1) audit build produksi Vite 8, (2) profiling langsung pada kernel Laravel untuk 13 endpoint utama, serta (3) uji beban dan konkurensi HTTP sebanyak 1.200 permintaan pada tingkat konkurensi 1 hingga 20. Kontribusi penelitian ini mengisi kesenjangan studi sebelumnya yang hanya mengevaluasi performa Client-Side Rendering (CSR) sisi klien tanpa membedah bottleneck query ORM, autentikasi JWT–RBAC, dan konkurensi API. Hasil pengujian menunjukkan sistem mencapai tingkat kegagalan 0,00%, puncak memori server 30 MB, waktu build Vite 263 ms, throughput publik 269,43–281,52 RPS, serta throughput admin JWT 125,92–164,58 RPS dengan latensi p95 di bawah 85 ms. Analisis mendalam juga mengidentifikasi tiga titik optimasi krusial: 39 query SQL pada dashboard analitik, N+1 query (8 query) pada daftar pengguna RBAC, serta ukuran bundle JavaScript tunggal 507,57 kB (151,72 kB gzip) yang memerlukan code splitting.
Kata kunci: hybrid monolith, jwt, laravel, performa web, react.js, ruang modal.
Abstract
The digital transformation of SMA Double Track alumni empowerment through the Ruang Modal Ecosystem—integrating Ruang Modal, Ruang Tumbuh, Ruang Pasar, and Monitoring—demands a reliable, secure, and responsive web architecture. Migrating the platform from a spreadsheet-based script to a Hybrid Monolith built with Laravel 13, React.js 18, Vite 8, Redux Toolkit, TanStack Table, TanStack Chart, JSON Web Token (JWT) authentication, and Spatie Role-Based Access Control (RBAC) introduces new performance challenges across frontend and backend layers. This study conducts an end-to-end performance analysis covering frontend bundle efficiency, server-side SQL query and memory profiling, and HTTP concurrency load resilience. Using a quantitative descriptive experimental approach across three layers—(1) Vite 8 build inspection, (2) Laravel kernel profiling across 13 core endpoints, and (3) live HTTP load testing of 1,200 requests at concurrency levels 1–20—this research addresses the gap left by prior client-side rendering (CSR) studies that overlooked ORM bottlenecks, JWT–RBAC overhead, and concurrent API throughput. Results confirm a 0.00% error rate, 30 MB peak memory, 263 ms Vite build time, 269.43–281.52 RPS public throughput, and 125.92–164.58 RPS JWT-authenticated admin throughput with p95 latency under 85 ms. Three optimization targets were identified: 39 SQL queries in the analytics dashboard, an N+1 query pattern in RBAC user listing, and a 507.57 kB monolithic JavaScript bundle requiring route-based code splitting.
Keywords: hybrid monolith, jwt, laravel, react.js, ruang modal, web performance.

1 Pendahuluan

Program SMA Double Track merupakan inisiatif strategis pendidikan menengah di Indonesia yang membekali peserta didik dengan keterampilan vokasional dan kewirausahaan guna menekan potensi pengangguran lulusan sekolah menengah [1], [2]. Keberhasilan penumbuhan jiwa kewirausahaan tersebut menuntut ekosistem berkelanjutan pasca-kelulusan yang mencakup pendampingan, fasilitasi permodalan, serta akses pemasaran produk alumni [3], [4]. Menjawab kebutuhan tersebut, dikembangkan Ekosistem Alumni SMA Double Track berbasis web yang mengintegrasikan empat layanan utama: Ruang Modal, Ruang Tumbuh, Ruang Pasar, dan Monitoring.

Migrasi sistem dari arsitektur awal berbasis Google Apps Script dan spreadsheet menuju arsitektur Hybrid Monolith (Laravel 13 + React.js 18 + Vite 8 + Redux Toolkit + TanStack Table/Chart + JWT Auth + Spatie Permission) secara signifikan meningkatkan keamanan, keteraturan data relasional, dan kekayaan antarmuka. Namun, penggabungan pustaka modern dan lapisan keamanan tersebut berpotensi memengaruhi ukuran bundle klien, efisiensi kueri basis data, serta kapasitas layanan saat diakses bersamaan [5], [6], [10].

Penelitian terdahulu oleh Cahyono et al. [5] telah mengevaluasi performa Client-Side Rendering (CSR) pada Hybrid LMS menggunakan metrik Core Web Vitals (Google Lighthouse) pada variasi jaringan 4G dan 5G. Studi lain [6]–[8] turut membandingkan performa rendering berbasis Lighthouse dan GTmetrix, sedangkan [10]–[12] mengevaluasi throughput REST API Laravel. Meskipun demikian, merujuk pada keterbatasan eksplisit pada [5], masih terdapat celah penelitian: evaluasi sebelumnya berfokus pada sisi klien tanpa mengaudit lapisan backend (jumlah query SQL, fenomena N+1 query ORM, overhead JWT–RBAC, dan puncak memori server) serta belum mengukur ketahanan beban konkuren HTTP (RPS dan latensi persentil p50/p95/p99). Selain itu, [5] secara eksplisit menyarankan eksplorasi code splitting untuk menekan beban eksekusi JavaScript. Oleh karena itu, penelitian ini menyajikan evaluasi empiris performa full-stack terhadap Ekosistem Ruang Modal berbasis web untuk memetakan bottleneck lintas lapisan dan merumuskan prioritas optimasi terukur.

2 Tinjauan Literatur

2.1 Ekosistem Digital Alumni SMA Double Track

Program SMA Double Track membekali siswa dengan life skill vokasional yang relevan dengan kebutuhan industri dan wirausaha mandiri [1], [2]. Kajian strategis [3], [4] menekankan pentingnya keberlanjutan pendampingan alumni melalui wadah terpadu yang menghubungkan kebutuhan alat kerja/modal usaha, mentor, dan etalase pasar secara terukur.

2.2 Arsitektur Hybrid Monolith, JWT Auth, dan RBAC

Pola Hybrid Monolith Laravel–React–Vite menyatukan penyajian REST API dan SPA dalam satu repositori sehingga menghilangkan kompleksitas CORS sekaligus menjaga performa respons tinggi [10]–[12]. Kombinasi JWT (RFC 7519) dan RBAC memberikan autentikasi stateless dan kontrol izin granular [13], [14], namun tetap memerlukan audit terhadap biaya kriptografi bcrypt dan pengecekan relasi izin di basis data [15].

2.3 Evaluasi Performa Web Full-Stack

Kualitas pengalaman pengguna (QoE) ditentukan oleh sinergi efisiensi sisi klien dan kecepatan respons server [9]. Pada aplikasi React berbasis CSR, bundle JavaScript besar memperburuk Total Blocking Time dan dapat diatasi dengan code splitting serta lazy loading [5], [16], [17]. Sementara pada sisi server, N+1 query ORM dan kueri berulang dalam loop menjadi penyebab utama degradasi latensi ketika jumlah data dan konkurensi pengguna meningkat [18].

4.4 Rekomendasi Optimasi Prioritas

Prioritas optimasi direkomendasikan secara bertahap: (P1) konsolidasi 39 kueri DashboardController menjadi 4 kueri GROUP BY disertai Cache::remember() dan penerapan React.lazy() untuk memecah bundle 507,57 kB [17]; (P2) perbaikan N+1 query pada RoleUserController melalui eager loading roles.permissions [18] serta server-side pagination; dan (P3) penerapan php artisan optimize, Redis, serta Nginx + PHP-FPM atau FrankenPHP pada lingkungan produksi [12].

5 Kesimpulan

Ekosistem Ruang Modal berbasis web (*Hybrid Monolith* Laravel 13 + React.js 18 + Vite 8 + JWT Auth + Spatie Permission) terbukti andal dan responsif dengan 0,00% kegagalan dari 1.200 permintaan konkuren, konsumsi memori 30 MB, waktu *build* 263 ms, *throughput* publik hingga 281,52 RPS, serta *throughput* admin JWT 125,92–164,58 RPS (p95 < 85 ms). Evaluasi *full-stack* ini melengkapi keterbatasan studi CSR sebelumnya dengan memetakan secara presisi 39 *query* dashboard, *N+1 query* RBAC, dan *bundle* JS 507,57 kB. Penelitian selanjutnya disarankan menguji dampak *before–after* optimasi P1–P2 secara inferensial pada infrastruktur produksi Nginx/FrankenPHP, MySQL/PostgreSQL, dan Redis.
